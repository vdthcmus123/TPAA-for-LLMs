# AI Tutor Evaluation — Baselines

This project builds supervised NLP baselines on the MRBench release associated
with *Unifying AI Tutor Evaluation* (NAACL 2025). It is the first stage of the
course project; collection and evaluation on a new dataset are a later stage.

## Scope of this stage

- Flatten MRBench into response-level examples. One row is one tutor response
  paired with its conversation context and the eight human annotation labels.
- Train Naive Bayes with TF-IDF, Random Forest with mean Word2Vec embeddings,
  and a multi-task BERT classifier.
- Keep every response from one conversation in the same train or test split.
- Report accuracy, macro-F1, weighted-F1, and per-class scores for each
  pedagogical dimension.

The classical and BERT models predict human labels; they do not generate tutor
responses. Zero-shot LLM tutoring and LLM-as-judge experiments belong to a
subsequent stage.

## Dataset

The source file is `data/raw/MRBench_V1.json`, downloaded from the paper's
official repository. The raw file is retained unchanged. `data/processed/` and
`reports/` are generated by the commands below.

The paper reports 192 dialogues: 60 Bridge and 132 MathDial, with 1,596 tutor
responses. The current GitHub V1 JSON also contains 192 dialogue objects, but
its observed composition is 53 Bridge and 139 MathDial, giving 1,589 response
rows. Four `conversation_id`s occur twice with the same history but different
tutor responses; those variants are retained as response examples and grouped
into the same split. This leaves 188 unique conversation IDs. The audit records
these differences rather than silently changing or inventing data.

The JSON's provided split is source-confounded (all 139 MathDial dialogue
objects are in `test`; Bridge objects appear in `train`, `val`, and `test`).
Therefore the baseline creates a deterministic, source-aware split by unique
`conversation_id` and does not use the provided `Split` field for model
evaluation.

## Run

Python 3.10+ is recommended. The active workspace runtime already has NumPy,
pandas, scikit-learn, PyTorch, and Transformers. The Word2Vec implementation is
Skip-Gram with Negative Sampling in PyTorch, so Gensim is not required.

```powershell
python src/baseline.py audit
python src/baseline.py run --model nb
python src/baseline.py run --model rf
python src/baseline.py run --model bert
python src/baseline.py run --model all
```

The BERT command uses the compact `google/bert_uncased_L-2_H-128_A-2`
checkpoint by default. On first use, Transformers needs access to Hugging Face
to download the checkpoint; pass `--bert-model bert-base-uncased` to select the
standard BERT-base model instead. A cached checkpoint can be used offline with
`--offline`. Unless `HF_HOME` is already set, the cache is stored under
`.cache/huggingface/` in this project.

For a quick CPU run, use `--w2v-epochs 2 --rf-trees 100 --bert-epochs 1`.
These flags reduce runtime and are not the recommended final experiment
settings.

## Outputs

- `data/processed/mrbench_v1_responses.csv`: normalized response-level table.
- `reports/data_audit.json`: actual counts, annotation completeness, label
  distributions, and differences from the paper's reported counts.
- `reports/split_manifest.json`: the fixed conversation-level train/test IDs.
- `reports/metrics_<model>.csv`: per-dimension metrics.
- `reports/predictions_<model>.csv`: test predictions for error analysis.
- `reports/metrics_<model>.json`: aggregate and per-class evaluation details.
- `reports/baseline_summary.md`: current results and the paper-to-release audit.

## Open-model Kaggle reproduction

`notebooks/kaggle_mrbench_open_llm_benchmark.ipynb` prepares a Kaggle GPU run
using Hugging Face weights for Llama 3.1 8B Instruct, Phi-3 Mini Instruct,
Mistral 7B Instruct, Prometheus 2 as an optional judge, and Qwen2.5 7B as an
additional model. Model IDs are approximate because the paper omits exact
checkpoint revisions. The notebook samples judge scores and does not yet
reproduce the paper’s full Pearson annotation-correlation experiment. It
recomputes DAMR from the released annotations, generates fresh tutor responses,
and exports a human-annotation template. Llama 3.1 405B is documented as
outside typical Kaggle GPU capacity. Fresh LLM outputs are not directly
comparable with the paper's human DAMR until they receive human annotations.

## Reproducibility and interpretation

The split seed is 42. Bridge and MathDial are split separately to keep both
sources represented in train and test. All eight output dimensions are trained
as separate classifiers for Naive Bayes and Random Forest; BERT shares one
encoder and has eight classification heads. The report always includes class
support because some classes, notably `Offensive`, are rare and their scores
are not reliable estimates with this dataset size.

This is a new supervised-classification experiment on the released labels, not
a full reproduction of the paper's model-generation study. Do not compare its
classifier F1 directly with the paper's DAMR or Annotation Correlation (AC).
Those paper metrics can be implemented as a separate analysis of the existing
tutor annotations.
